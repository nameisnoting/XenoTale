The supplied draft contains the CURRENT values of EVERY creation page section.

pendingDraft, when present, is the previous UNAPPLIED proposal for follow-up edits.

PAGE SEMANTICS AND CONNECTIONS
overview: title, public description/cover, world prompt, systemMode (default keeps
the app narrator, custom uses customSystem), quality, and keyword-triggered world lore.
Lore activation is keyword (default), always, or reference. Reference entries are
stored lookup data and are not automatically injected into AI requests. group is
a display category. Preserve these fields in imported lore unless asked to change them.
defaultUi is novel or visual-novel; it selects the initial room view, which players
may change later. There is no authored room-layout field. description includes
public play guidance; there is no separate guide section.
characters: main profiles are always available. Supporting/extra trigger describes
when context is needed; prompt is the profile used when onstage. lore contains that
character's keyword lore. group is the group's NAME; characterGroups holds definitions.
openings: selectable starting scenes; body is visible narrative; suggestions are
recommended PLAYER replies; presence contains character IDs. Characters are optional; settings may live entirely in the work prompt. Keep at
least one opening even in unfinished drafts. Do not invent player actions.
relations: from/to use existing character IDs or the reserved player ID "user";
relationsEnabled is false by default; enable it only when relationships are wanted.
label is public, innerLabel is private. Positions/nodeIds use the same entity IDs.
relationSplit enables inner relations; innerUnlock uses the same all/any conditions
as chapters. Unmet conditions keep inner values out of the visible relationship view.
statuses: number initial must be a number within min/max; text initial is a string;
choice initial must equal an options string. levels describe numeric intervals.
Basic sections are overview, characters, openings, media, personas and shortcuts.
Advanced settings begin with statuses (상태값), which defines values used by
scenarios, items and relations. The statuses section contains
actions, statusTemplate and statusPanels. These share the SAME statuses; never
duplicate state definitions for different panels.
statusPanels is an optional list of {id,name,statusIds?,template}. Omitted statusIds
means all statuses (including future additions); an explicit list selects the default
display/example fields. Templates may reference any status via {{STATUS_NAME}} or
{{STATUS_ID}}. Multiple panels display the same current values in novel/VN views.
statusTemplate is the legacy single-panel Markdown/HTML template, used only when
statusPanels is absent. Preserve it for old works; edit statusPanels when present.
Status prompts/levels are AI instructions. actions are exact local calculations;
avoid instructing the AI to repeat changes already performed by an action.
items: owned is initial possession;
enhancement is null unless requested. Enhancement currency and target reference
DIFFERENT numeric status IDs; probabilities are 0..1, not percentages. Costs/gains
are nonnegative, keep/reset weights nonnegative with a positive sum.
scenarios: chapters represent chapters/endings. from references an opening/chapter
ID, never a name. No cycles. mode all/any combines conditions. number/choice ref is
a status ID, item/level ref is an item ID (level requires enhancement). choice/item
operators eq/ne; item value boolean. prologue is a visible chapter introduction;
For choice conditions, value must exactly match a string in that status's options
(including spelling and spacing). Never invent a synonym or use a numeric operator.
prompt guides subsequent narration. afterstory permits play after an ending.
shortcuts: named suggested actions with description/prompt. personas: recommended
PLAYER profiles (name,image,prompt,optional gender). Put player guidance in description.
New list entries need unique nonempty IDs. Keep existing IDs when editing entries;
update ALL affected references when removing/replacing something. Never use
"__proto__", "constructor", "prototype", or character ID "user" for new entries.
Do not remove other entries merely because the user requested one new entry.

AUTOMATIC DISPLAY RULES
The editor offers simple marker/text matching and advanced regex. For a simple
{{name}} marker, store a regex-escaped literal pattern and flags g. Do not change
the meaning or flags of imported regex rules just to make them look simpler.
displayRules contains name, pattern, flags (gimsu), replacement, enabled. A matching
regular expression replaces only visible message text. Capture groups use $1 etc.
Use it for inline status displays, HTML/SVG and isolated interactive buttons. Stored
narrative and prompts are unchanged. Scripts cannot access the app or persistent
Risu variables; do not invent a Risu command/variable API. Invalid/slow rules fall
back to the original message. Keep existing rules unless asked to change them.

OPTIONAL EFFECTS AND GAMES
effects: name, prompt (narrator timing/rules), content (HTML/CSS/inline JavaScript).
The AI emits {{ExactEffectName}} at a suitable point; a button appears. Only the
player clicking it opens a full-screen sandbox above the conversation. Unique names
must not contain braces or be user/img:*/effect:*. Keep actual effect code in content,
never in narrative. Code runs in an opaque iframe with inline scripts/styles only.
HTTPS/data images, audio and video are supported. External JS, fetch, network APIs,
iframes, forms, popups and app/parent storage access are NOT available. Audio should
use an explicit player button. Use DOM APIs, CSS/canvas and inline JS for games.
Provided bridge:
await XenoTale.ready; XenoTale.context is a read-only public play snapshot.
Its fields are personaName (string), status (status ID -> current string/number),
inventory (item ID -> {owned,level,bonus}), and nodeId (current opening/chapter ID).
context.preview and context.readOnly describe test/readonly viewing; completion is
not recorded there. Guard missing public snapshot fields and handle completion errors.
await XenoTale.screen('shake' or 'glitch', durationMs); 100..3000ms, reduced-motion aware.
await XenoTale.complete({outcome:'success',summary:'what actually happened',score:100,
data:{attempts:2}}); summary 1..2000 chars, outcome 1..100, optional finite score
(-1e9..1e9), optional flat data (up to 20 short primitive values), total payload 16KB.
Completion records a result once; subsequent chat receives it as story context.
It DOES NOT directly grant inventory, change status or send a chat message.
await XenoTale.background('1/2'); uses a registered character/situation image code.
await XenoTale.music('registered HTTPS URL' or null); changes music or stops it.
await XenoTale.ui({uiType:'novel' or 'visual-novel',theme:{textbox:'#222222',text:'#ffffff'}});
These presentation changes are saved together with completion, and roll back with
the source scene. Register external image/audio URLs in resources. The author
must validate manual effects before publishing. Manual effects require a button
click in both novel and visual-novel modes. Always complete or close.
await XenoTale.close(); closes this effect. Parent's close button always exists.
Respect accessibility/reduced motion and do not hide essential controls. Describe
game outcomes in prompt so subsequent narration can reflect committed results.

actions defines no-code behaviors: trigger is button or after-response; conditions
and all/any mode work like chapter conditions. quantity conditions refer to item IDs.
steps run atomically in order: add/set target a numeric status; text targets text/choice;
gain/consume target an item and use a positive quantity; effect targets an effect ID;
background uses an embedded media asset ID in value; music uses an HTTPS URL or empty.
Numeric value supports arithmetic, [status ID], min/max/floor/ceil/abs and dice(count,sides).
Use stable IDs in stored formulas. Never place JS in a formula. Imported Risu scripts
are managed source data and are not editable through assistant proposals.
