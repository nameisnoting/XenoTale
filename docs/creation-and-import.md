## 직접 업로드한 이미지

미디어에서 직접 업로드/외부 URL을 선택할 수 있습니다. PNG·JPEG·WebP·GIF를
올리고 이름을 정하면 AI는 `{{웃음}}`처럼 그 이름으로 이미지를 표시할 수 있습니다.
이미지 바이트는 브라우저 IndexedDB의 assets 테이블에 따로 보관합니다. 작품 데이터에는
`asset:SHA256` 참조가 들어가며, 동일한 바이트는 한 번만 저장합니다. API 요청에 이미지
바이트를 넣지 않고 이름과 사용 문법만 보냅니다. 이미지 이름을 바꾸면 이미 작성된
도입부나 메시지의 태그도 직접 맞춰야 합니다.

파일 하나의 내장 이미지 상한은 **2GiB·10,000개**, 작품 설정 JSON 상한은 50MiB입니다.
진행률과 사용량을 표시하며 한도를 넘으면 저장 전에 알립니다. 전체 백업도 같은 파일
상한을 사용하므로 여러 대작의 합계가 넘으면 작품별로 내보내야 합니다. 실제 가능한
크기는 브라우저 저장 용량과 메모리에 달려 있습니다. 2GiB 실파일의 스트레스 테스트를
통과했다는 의미는 아닙니다. 웹사이트 데이터를 지우기 전에 파일로 백업하세요.

## .xeno 파일

작품·작업공간·대화방·전체 백업을 ZIP 기반 .xeno로 내보냅니다.
`content.json`은 설정/대화, `assets.json`은 이미지 목록, `assets/해시`는 실제 바이트입니다.
참조하는 이미지만 중복 없이 넣습니다. 가져올 때 파일 크기·참조·SHA-256을 확인하고,
저장 데이터와 이미지를 같은 IndexedDB 트랜잭션에 넣습니다.

이 파일은 **암호화된 파일이 아닙니다**. API 키는 기존 전체 백업 옵션을 따른 별도
자격증명 데이터이며, 일반 작품 파일에는 포함되지 않습니다. 제작 헤더의 작품 불러오기는
현재 작업을 덮어쓰지 않고 새 작업공간으로 엽니다. 기존 라이브러리 가져오기도 유지합니다.

### 설치형 웹앱과 더블클릭

데스크톱 Chrome/Edge 등 파일 처리를 지원하는 브라우저에서 XenoTale을 앱으로 설치하고
운영체제의 .xeno 파일 연결을 허용하면, 파일을 열 때 앱이 받아 새 대화방을 만듭니다.
아직 제작 중이라 플레이 조건을 만족하지 않는 파일은 작업공간으로 엽니다.
전체 백업은 자동 병합하지 않고 일반 가져오기로 복원하도록 안내합니다.

앱이 사용자의 설치·파일 연결 권한을 스스로 허용하지는 않습니다. 브라우저가 설치를
제안할 수 있을 때 메인 화면에 앱 설치 버튼을 표시합니다. 지원하지 않는 환경에서는
웹페이지의 파일 불러오기를 사용합니다. 모바일 파일 연결 지원은 브라우저별로 다릅니다.
서비스 워커는 앱 화면과 불러온 정적 파일을 캐시합니다. 오프라인 AI 응답은 지원하지 않습니다.

공식 동작: [Chrome File Handling API](https://developer.chrome.com/docs/capabilities/web-apis/file-handling),
[MDN file_handlers](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/file_handlers).

## Risu 파일 변환

.charx ZIP, ZIP이 붙은 JPEG, V2/V3 카드 메타데이터가 든 PNG, 카드 JSON을 읽습니다.
PNG에 V2/V3가 함께 있으면 V3를 우선합니다. 제작자 코드나 원문을 서비스 코드에 복사하지
않고 카드 파일 형식만 독립적으로 읽습니다. 원본 Risu 파일은 변경하지 않습니다.

| Risu 내용                                       | XenoTale 대응                     |
| ----------------------------------------------- | --------------------------------- |
| 이름·제작자·제작자 설명                         | 작품 제목·제작자·공개 설명        |
| description/personality/scenario/예시/후속 지침 | 작품 프롬프트                     |
| system_prompt                                   | 있으면 사용자 시스템 프롬프트     |
| 첫 인사·대체 인사                               | 도입부 목록, 없으면 시작 안내문   |
| 활성 character_book                             | 키워드·항상 사용·참조 자료 로어북 |
| 내장 래스터 이미지                              | 표지와 이름 있는 업로드 이미지    |
| editdisplay 정규식                              | 자동연출 표시 규칙                |

호환 가능한 표시 규칙은 자동으로 켭니다. Risu 변수·명령이 필요한 규칙은 끈 상태로
보관합니다. `module.risum`, Lua/가상 스크립트, 트리거, Risu 전용 변수·배경 HTML은
아직 실행하지 않습니다. 가져온 원본 파일 전체를 별도의 자산으로 저장하고
`work.importSource`에서 참조하므로, .xeno 재저장 후에도 미지원 데이터의 원본 바이트를
보존합니다. 원본은 자동 실행하거나 AI에게 전송하지 않습니다.

로어북의 폴더 항목은 빈 로어북으로 만들지 않고 각 항목의 분류로 옮깁니다.
`constant`는 항상 사용, 유효한 키워드가 있는 항목은 키워드 사용, 키워드가 비어 있거나
지원하지 않는 정규식·보조 키워드 조건이 있는 항목은 참조 자료로 보관합니다.
참조 자료는 AI에게 자동 주입하지 않습니다. Lua의 이름 기반 조회는 아직 연결되지
않았습니다. 로어북은 20개씩 표시하며 이름·분류·키워드로 검색할 수 있습니다.
Risu 우선순위·토큰 예산·복합 활성 조건은 아직 동일하게 구현하지 않았습니다. 불러오기 확인창에서 차이와 누락을 안내합니다. Risu TRPG의 버튼으로 앱 상태를
수정하는 기능까지 완전 호환된다는 뜻은 아닙니다.

제공된 예시를 직접 확인하고 변환→.xeno 저장→재불러오기를 검사했습니다.

| 예시                       | 컨테이너  | 확인한 내용                                                        |
| -------------------------- | --------- | ------------------------------------------------------------------ |
| 고쇼가와라 히지리.charx    | ZIP       | 내장 표지, module.risum, 원본 인사 없음                            |
| CharX Embeded Jpeg(3).jpeg | JPEG+ZIP  | 내장 표지, 로어북 3개, module.risum                                |
| 던전 앤 다이스.png         | PNG V2/V3 | 도입부 2개, 원본 로어북 971개 → 폴더 5개와 내용 966개, 정규식 25개 |

원문 설정은 공개 문서나 테스트 코드에 복사하지 않았습니다.

## HTML · 자동연출 · 수동연출

일반 대화와 작품 설명은 Markdown, HTML/CSS, SVG를 격리 iframe에서 표시합니다.
올바른 HTML 이미지 문법은 `<img src="https://...">`입니다. 일반 메시지의 스크립트와
이벤트 속성은 실행하지 않습니다. HTML 내부의 상대경로 대신 HTTPS 또는 내장 이미지
참조를 사용하세요.

자동연출은 정규식으로 **화면에 보이는 내용만** 바꿉니다. 저장 원문과 AI 입력은 바꾸지
않습니다. `$1` 등 캡처 치환, g/i/m/s/u 옵션을 지원합니다. 이미지/연출 태그 사이의
텍스트 덩어리 단위로 처리하므로 일반 문단 사이 줄바꿈은 매칭할 수 있습니다.
비주얼노벨은 현재 대사 페이지 단위로 표시합니다. 느린 정규식은 별도 Worker를 종료하고
원문을 표시합니다. 등록된 치환 내용의 허용된 인라인 스크립트와 버튼 이벤트는 iframe
안에서 실행합니다. 버튼의 DOM 상태는 해당 표시의 수명 동안만 유지됩니다.

iframe은 allow-scripts만 허용하고 앱과 같은 출처 권한은 주지 않습니다. CSP·HTML 정제와
코드 검사를 함께 사용합니다. 앱 저장소·API 키를 넘기지 않으며 Risu 변수 API도 없습니다.
이는 임의 코드를 완전한 악성코드 검사로 증명하는 기능이 아닙니다. 허용된 외부 이미지
주소에는 브라우저가 요청을 보내므로 신뢰할 수 없는 리소스를 등록하지 마세요.

수동연출은 AI가 `{{연출이름}}`을 내보내면 보기 버튼을 표시합니다. 소설과 비주얼노벨
모두 사용자가 버튼을 눌러 엽니다. 작성한 연출은 기존 미리보기·유효성 검사를 거쳐야
출판할 수 있습니다. `XenoTale.ready/context/screen/complete/close`와 함께 다음 API를
사용할 수 있습니다. 등록된 리소스만 참조하세요.

```js
await XenoTale.ready;
await XenoTale.background('1/2');
await XenoTale.music('https://example.com/registered-bgm.mp3'); // null: 끄기
await XenoTale.ui({ uiType: 'visual-novel', theme: { textbox: '#222222', text: '#ffffff' } });
await XenoTale.complete({ summary: '연출 결과' });
```

연출을 완료하면 결과와 화면 변경을 저장합니다. 완료 전 닫으면 임시 변경을 취소합니다.
리롤·삭제·응답 후보 변경은 해당 응답의 연출 결과도 되돌립니다. 챕터·엔딩 BGM은 미설정이면
이전 음악을 잇고 빈 주소이면 끕니다.

## 관계도 · 비주얼노벨

새 작품의 관계도 사용은 OFF입니다. OFF에서는 편집 영역을 흐리게 표시하고 대화방
메뉴에서도 숨깁니다. 내면 해금은 챕터와 같은 아이템/강화 단계/숫자/선택 상태 조건을
all/any로 결합합니다. 잠겨 있을 때 내면 값을 화면에 표시하지 않습니다.

비주얼노벨 이미지는 세로≥가로이면 영역 높이, 가로>세로이면 영역 너비를 맞춥니다.
비율을 유지하며 가운데에 놓고 영역 밖은 자릅니다. 장면 이미지가 없으면 작품 표지만
표시합니다. 낮은 해상도의 원본을 확대해도 세부 묘사가 새로 생기지는 않습니다.
눈 버튼으로 메시지 영역의 UI를 숨기고 아무 곳이나 클릭/터치하면 다시 표시합니다.

## 던전 앤 다이스: 확인한 실행 의존성

사용자가 제공한 PNG의 Lua는 약 130만 자이며 캐릭터 생성, 능력치, 전투, 주문, 상점과
표시 갱신이 연결되어 있습니다. 이를 앱 코드로 복사하거나 실행하지 않고 구조만 확인했습니다.
`K.Cg.click`이 종족·직업·배경·능력치 방식·스킬·장비 선택을 처리하고, 선택은
`dnd_cg` 상태에 저장합니다. `K.loreBody`는 `getLoreBooks`로 이름이 일치하는 자료를 찾습니다.
따라서 몬스터·주문 항목에 키워드가 없는 것은 원본의 누락이 아닙니다.

현재 구현은 이 Lua를 실행하지 않습니다. 다음 호환 작업에서 검증할 최소 흐름은
다음과 같습니다. 이것은 구현 완료 보고가 아닌 작업 기준입니다.

1. 원본 Lua를 격리된 실행기에 로드하고 이벤트 핸들러를 등록한다.
2. getState/setState, getChatVar/setChatVar, getLoreBooks와 원본이 참조하는 대화 조회·표시 API를 연결한다.
3. 생성 화면을 출력하고 종족·직업·배경 선택 버튼을 원본 콜백으로 전달한다.
4. 클릭의 상태 변경을 한 사건으로 저장하고 재표시에서는 변경을 반복 실행하지 않는다.
5. 새로고침 복원·이전 시점 분기·재생성의 상태 복원을 검사한다.
6. 생성 완료 내용을 AI 요청에 반영한 다음 스킬·상점·전투의 지원 범위를 넓힌다.

Lua 로드나 첫 버튼 하나가 성공했다고 원본 전체 플레이가 호환된다고 판단하지 않습니다.
